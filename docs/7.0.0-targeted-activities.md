# 7.0.0：工程与外援

本版保留现有王国回合页面和扎营流程，不安装或复制外部辅助插件代码。

## 使用

1. 所有 GM/玩家刷新。若启用了 `vk-kingdom-turn-helper`，先停用它以免双重处理。
2. 保留现有活动启用设置；在领导活动使用“加速项目”或“请求外援（V&K）”。
3. 加速项目先选本王国聚落场景内的未完成建筑，再使用原王国检定窗口。成功后选择投入 RP，取消投入可从“工程与外援记录”继续。每建筑每回合一次。
4. 外援使用现有外交团体选择器。首次操作只补充稳定标识，不改名称或谈判 DC。检定完成才记录次数；取消选择或未掷骰不占次数。
5. 外援 DC 为谈判 DC + 2 + 历史累积值。后续请求增加 2；每个未请求回合降低 1，最低为 0。使用统一的王国回合计数，不监听聊天文字、不依靠计时器清零。

## 中断恢复

工程投入先在队伍上一次保存扣除 RP 和投入凭据，再在建筑上一次保存 HP 进度和同一凭据。两份文档不是跨文档原子事务。

若中断，打开“工程与外援记录”，选择“继续待处理投入”。已有凭据不会再次扣 RP 或增加进度。若建筑被移动、删除或进度被外部修改，GM 应检查并手动修正 RP/进度，再使用“人工核对后标记已处理”。此按钮本身不会退款或修改建筑。未完成投入不阻止整个王国结束回合。

原生王国检定若自身中断，仍使用原有“核对未完成的王国检定”入口；此版本没有重写全局检定恢复或扎营策略。

## 本版边界

- 外援只接入目标记录与 DC；奖励仍由原结果卡处理。成功的 RP 与加值选项不可同时领取，掷骰后使用加值、援助 RP 不转 XP 仍需 GM 核对。
- 不追溯推断旧外援记录；升级前手动增加过基础谈判 DC 的团体，请 GM 核对，避免叠加旧的人工增量。
- 持续施工沿用现有王国规模额度，新增本回合累计投入及加速大失败惩罚。分类建筑额度和开工回合自动追踪不在本次范围；本回合刚开工的建筑是否允许持续施工仍由 GM 核对。
- 进度沿用现有建筑 HP 表示。只枚举本王国登记的聚落场景，不搜索整个世界。
- 切勿在存在工程记录时随意把王国回合计数往回调；记录按实际回合编号归属。
- 无启动时迁移、自动导入建筑、全局骰子替换或 DOM 观察器。

## 数据与回退

新记录保存在队伍的模块 flags：`turnProjects`（schema version 1）及 `projectGroupIdsVersion`；团体新增 `id`，建筑有 `projectPayments` 收据。保留历史用于故障恢复，不自动清空。

使用前备份世界。回退 6.4.9 不会撤销已经扣除的 RP 或建筑进度，也不会自动删除新记录；需要撤销游戏结果时，应从配套世界备份恢复，而不只是降级插件。

## 验证

自动测试覆盖原生检定回调接线、取消、DC/回合变化、稳定团体标识、改名、累计额度、双客户端、重复请求、两步保存确认丢失、失败恢复及人工核对权限。构建检查同时核对嵌入的英文词典。测试边界模拟不是 Foundry 世界内 UI/多人验收；发布时须分别说明。
